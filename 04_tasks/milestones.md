# Milestones

## Milestone A — Repo Headquarters Stable

### Outcome

The repository is coherent enough to function as a long-term project headquarters.

### Included

- governance established
- design spine established
- system doctrine established
- task and testing lanes active

### Completion Signal

Team can navigate the repo and understand where truth lives.

## Milestone B — Local Prototype Readiness

### Outcome

Local test workflow is stable enough to support repeated system iteration.

### Included

- local setup documented
- first prototype target areas chosen
- first test plan scenarios defined

### Completion Signal

A local two-player loop can be repeated intentionally.

## Milestone C — Death and Continuity Prototype

### Outcome

The project proves that meaningful loss and continued play can coexist.

### Included

- first death-routing model
- continuity rules
- backup-character practical assumptions
- early anti-abuse thinking

### Completion Signal

Losing a character hurts in testing without ending the session’s viability.

## Milestone D — Wounds, Recovery, and Hunt Identity

### Outcome

Combat aftermath and pursuit begin to feel distinctly Neo UO.

### Included

- wound or incomplete recovery prototype
- tracking clue prototype
- first pursuit pressure assumptions
- first mobility consequences

### Completion Signal

A fight can create a meaningful after-state instead of a clean reset.

## Milestone E — Sparse World Pressure Prototype

### Outcome

The world begins to feel quieter but more meaningful.

### Included

- lower-density pressure assumptions
- scarcity direction
- early carry / logistics implications
- more meaningful encounter placement assumptions

### Completion Signal

The world feels less cluttered without feeling dead.

## Milestone F — Closed Identity Playtest

### Outcome

Outside players can test whether Neo UO feels distinct in practice.

### Included

- controlled tester group
- structured playtest note capture
- first friction / tension findings
- first real adjustment loop

### Completion Signal

The project has external evidence about whether the intended experience is landing.

This pass should make the repo noticeably more operational and much clearer about what comes next.
